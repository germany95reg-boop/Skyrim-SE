# Skyrim SE Mobile — автоматические проверки разработки

Главный процесс: `.github/workflows/android-quality-gates.yml`. Он запускается на каждом Pull Request в `main`, при обновлениях `main` и при изменениях рабочей ветки автоматизации. Новые версии APK **не публикуются пользователю из-за каждого мелкого исправления** — создаётся только временный артефакт CI с семидневным сроком хранения.

## Три обязательных этапа

1. **JVM / без Android** — `mobile/ci/run_jvm_suite.sh` находит все актуальные `mobile/tests/*Test.java`, компилирует вместе с production-парсерами и выполняет каждый тест. Защита от регрессий BSA 105, NIF, материалов, DDS, нормалей, безопасности размеров, сборного атласа, геометрии, установочного пакета. Тестовые NIF/DDS генерируются программно; коммерческие ресурсы Skyrim не включаются.
2. **Vulkan + Android APK** — скрипт `mobile/ci/setup_android_build.sh` устанавливает Android SDK/NDK/CMake и компилирует все 8 GLSL-вариантов (включая резервные v2.14) в SPIR-V и проверяет их через spirv-val; Gradle строит настоящий ARM64 APK. `mobile/ci/verify_apk.sh` проверяет `applicationId`, versionCode, versionName, сертификат обновлений, отсутствие архитектуры x86_64 в обычной сборке, нативную библиотеку Vulkan и SPIR-V-ресурсы.
3. **Android-эмулятор** — отдельная CI-сборка добавляет `x86_64` **только с `-PciEmulator=true`**, без изменения скачиваемого ARM64 APK. `AndroidUiSmokeTest` запускает настоящие Android Activity, проверяет кнопки NIF/DDS, реакцию без выбранного архива, локальный WebView и повторное создание Vulkan-окна. Результаты JUnit сохраняются отдельно при любом исходе.

Любой провал этапа помечает GitHub Actions как ошибочный. Никакой «успешной сборки» по одному факту появления файла APK. Перед ручной выдачей пользователю проверяются все три этапа.

## Что можно проверять без пользователя

- Формат и безопасность NIF/BSA/DDS, точность связи `BSTriShape → shader → texture set`.
- Соответствие геометрии/UV, чтение материалов, создание текстурного атласа и защитные ограничения памяти.
- Компиляция GLSL, C++ и Android, наличие SPIR-V и `libskyrimse_scene.so`.
- Подпись и идентичность Android-пакета для установки обновлений.
- Базовые экраны, переходы, отсутствие сбоев при неполных данных и Android lifecycle.

## Что пока требует реального телефона

- Реальный результат рисования Vulkan на **Adreno**, правильность материалов/освещения, отсутствие графических артефактов.
- Реальные разрешения SAF на пользовательские BSA, особенности файловой системы смартфона, длительный игровой прогон, реальные FPS и нагрев.
- Полноценные проверки запуска SkyrimSE.exe не подходят: проект пока является **просмотрщиком ресурсов**, не игровым движком.

Эмулятор подтверждает работу основных Android-операций, но **не доказывает** визуальную корректность рендера на Adreno. Поэтому пользователю нужен один короткий аппаратный прогон **после крупного этапа разработки**, а не после каждой кнопки.

## Локальный запуск

```bash
cd mobile
gradle --no-daemon :app:dependencies --configuration debugRuntimeClasspath
bash ci/run_jvm_suite.sh
python3 tests/v213_contract_test.py
python3 tests/release_signing_contract_test.py
python3 tests/ci_quality_contract_test.py
```

Устройство/эмулятор с Android SDK и доступным x86_64-образом:

```bash
cd mobile
gradle --no-daemon -PciEmulator=true :app:connectedDebugAndroidTest
```

Для рабочей ARM64-сборки не передавать `-PciEmulator`: всё остаётся подписанным прежним сертификатом и устанавливается поверх старой версии.

## Правило выпуска

Промежуточные коммиты → автоматические тесты → исправление регрессий → завершение существенного функционального блока → единый APK, прямо в чате → один пользовательский отчёт о реальном Vulkan. Никаких коммерческих BSA внутри CI.
